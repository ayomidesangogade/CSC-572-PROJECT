# Phishing URL Detection: Code Package

This folder contains the full implementation for the "Machine Learning-Based System
for Phishing URL Detection" project proposal (Option A: pre-extracted UCI feature dataset).

## Files

| File | Purpose |
|---|---|
| `phishing_dataset.csv` | UCI Phishing Websites dataset (11,055 URLs, 30 features + label), with header row added |
| `Phishing_URL_Detection.ipynb` | Main notebook: EDA, model training, evaluation, feature importance, model export |
| `feature_extraction.py` | Converts a raw URL into the 30 model features in real time (used by the demo app) |
| `app.py` | Streamlit demo app: type in a URL, get a live phishing/legitimate prediction |
| `requirements.txt` | All required Python packages |
| `phishing_model.pkl` / `feature_columns.pkl` | Saved trained model and feature order (generated by the notebook) |

## Setup

```bash
pip install -r requirements.txt
```

## Running the notebook

Open `Phishing_URL_Detection.ipynb` in Jupyter or VS Code and run all cells top to bottom.
It will train and compare five models (Logistic Regression, Decision Tree, Random Forest,
SVM, XGBoost), evaluate them, and save the best-performing model as `phishing_model.pkl`.

## Running the demo app

Once the notebook has been run at least once (so `phishing_model.pkl` exists):

```bash
streamlit run app.py
```

Then open the local URL Streamlit prints in your browser, type in any URL, and click
"Check URL" to get a live prediction.

## Notes and limitations

- `feature_extraction.py` performs live DNS, WHOIS, SSL, and page-content checks, so it
  needs an active internet connection to analyze a new URL.
- Five of the original 30 dataset features (web traffic rank, PageRank, Google index,
  backlink count, statistical report membership) relied on third-party services that have
  since been discontinued or restricted. These are approximated with fixed default values;
  see the docstring at the top of `feature_extraction.py` for details. This is a known and
  documented limitation of working with this dataset today, and is worth mentioning in your
  report's limitations/discussion section.
- To pursue Option B from the proposal (building a fresh dataset from PhishTank/OpenPhish and
  the Tranco list), the lexical feature functions in `feature_extraction.py` can be reused
  directly as your feature engineering step.
